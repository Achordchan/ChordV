# 后台删除用户、套餐、订阅、团队

日期：2026-11-27。

## 背景

之前这四类数据只能停用。数据库里它们之间都是级联删除（删套餐会带走它的所有订阅，订阅带走流量账本、节点账号、会话等），一直没有开放删除接口。

## 行为

- `GET /admin/{users|plans|subscriptions|teams}/:id/delete-preview` 列出会一起删掉或受影响的数据（数量和最多 5 条示例）。
- `DELETE /admin/{users|plans|subscriptions|teams}/:id`：没有关联数据时直接删；有关联数据时必须带 `?force=1`，否则返回 409。
- 不能删除当前登录的管理员，也不能删除最后一个管理员（强制也不行）。
- 删账号会连同名下团队及其团队订阅一起删除；加入的其他团队只是移出。工单随账号删除；删订阅/套餐/团队时工单保留、解除关联。
- 管理端在客户详情“更多”菜单里有“删除订阅 / 删除账号 / 删除团队”，套餐详情里有“删除”。弹窗先读预览；有关联数据要勾选确认，按钮变成“强制删除”。

## 节点与客户端

- 删除前先撤销相关在线会话。
- 在删除的同一个事务里，给仍在服务这些账号的节点下发 `REMOVE_USER`（命令行与订阅/绑定没有外键，删除后仍保留），提交后再推送给 Agent。节点没有可用 Agent，或不在 `direct_primary` 控制模式（Agent 会拒绝写用户）时不下发，只计数并提示自行检查。
- Agent 在执行删除前可能还会上报这个账号的用量。计量现在把“绑定已不存在”的样本直接忽略，之前会返回 409，导致整个节点的用量队列卡住。
- 被删账号的客户端收到 `account_updated / auth_invalid` 退出登录；其他受影响用户收到 `subscription_updated`。
- 删账号后订阅链接随之删除，分发记录 `SubscriptionLinkPublication` 本来就不设外键，下一次对账（管理端写操作会立即触发）撤销 CF 上的键。

## 验证

`CHORDV_TEST_DATABASE_URL=.../chordv_deletion_test pnpm --filter @chordv/api test:deletion-postgres`：在真实 PostgreSQL 上跑预览计数、未强制拒绝、强制删除后的级联、`REMOVE_USER` 保留与推送、计量不再卡住、不能删自己/最后一个管理员、删账号带走名下团队。
