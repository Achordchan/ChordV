# 下载缓存清理与发布边界

## 客户端行为

- GEO 和 Xray 仍安装到固定文件名，校验通过后替换旧文件。下载中允许临时存在下载文件、解压或复制后的文件及旧版本。
- 下载作用域结束时清理本次 `.download` 和 `.part`，覆盖成功、取消、网络失败、校验失败和写入失败。清理失败写入 `download-diagnostics.log`，下次启动再次清理应用拥有的残留。
- 启动时恢复目标缺失的 `.previous` 备份；目标已存在时删除旧备份。一个缓存文件清理失败不阻止其他组件备份恢复。
- `installer-cache` 启动时删除已安装版本及更旧版本，只保留一个最新待安装版本；新包校验完成后只保留这次选中的包。只处理可识别的 ChordV 安装包，未知文件与目录不递归删除。
- Windows 先校验临时文件再保存安装包，安装仍使用官方更新器已验证的内存字节。
- Windows 官方更新器在系统临时目录留下的 `ChordV-<版本>-updater-*`，仅在没有安装进行中、目录及文件已超过 24 小时且内容完全符合官方安装器命名时清理；未知内容、符号链接及近期文件保留。
- 文件系统拒绝删除时记录错误并在后续启动重试，不保证被其他进程持续锁定的文件立刻释放空间。

## 后台与客户端发布

后台相同 GEO 内容仍进入持久清理队列，实际分发过的旧版本保留至少 30 天；后台历史文件不会全部同步给客户端。本次未更改这一兼容策略。

后台版本推进到 `0.0.21`，沿用 `Release Backend System` 发布及稳定清单推送；该后台版本本身不会让已有客户端获得原生清理修复。客户端版本号保持不变，等待之后明确安排打包和发布。

本次 PR 使用 `skip-desktop-packaging` 标签，跳过 Windows 测试安装包制作及依赖它的安装升级测试；保留 macOS/Windows 原生编译、单元测试及协议回归。无该标签的 PR 保持原有完整安装验证。
