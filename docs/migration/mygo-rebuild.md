# ChordV 本地 MyGo 重构验收

## 目标与边界

- 桌面客户端改为 MyGo + Go；保留 React/Mantine 现有界面、交互与主要窗口尺寸。
- 服务端改为 Go，保留账户、权限、节点、Agent、计量、订阅、团队、公告、工单、路由规则和设置业务，不以旧 Node.js 代理作为最终实现。
- 管理后台继续用浏览器访问，移除发布中心和上传、审批、候选发布流程。
- 安装包、服务端和运行组件以 GitHub Releases 为唯一发布真相；校验资产完整性，不在客户端嵌入私有仓库令牌。
- 仅本地开发、运行、测试；不推送 Git，不创建 Release，不触发部署，不连接线上数据库，不下发线上节点命令。

基线：`397a64d`；本地工作分支：`achord-agent/mygo-rebuild`。

## 验证口径

- 单元测试通过不等于端到端完成，端点存在不等于业务等价，页面能打开不等于视觉验收。
- 对照旧代码中的业务规则与回归测试，迁移或重写有价值的测试；失效的源码文本断言不能作为新实现正确的证据。
- 无法执行的跨平台、签名、安装、网络连接验证必须明确保留为未完成，不用推测替代实测。
- 用相同平台、架构、功能、压缩和缓存条件比较构建耗时、可执行体积和安装包体积，不以框架空应用宣传替代测量。
